# Independent official-submission review

**TRAINING_OR_ENGINEERING_USE_ONLY**

Reviewed the new browser modal and preview route against the existing signed-target, packet-integrity, provider-allowlist, employer-credential, nonce and durable-attempt controls. No provider call is made by preview construction. The caller's selected target is displayed and included in the signed approval; execution derives destination and transmitted fields from that approval and independently checks the frozen packet. Existing replay/uncertain-attempt behavior remains in force.

Found and repaired unnecessary private-data transmission: the browser sent the entire application record, including older résumé packets, recruiter contacts, private notes and timeline, though only the current packet and state are needed. The request now sends strict `{record:{packet,state},target,fields}`. The server rejects historical/private record fields; those values are not reflected in errors. Authentication denials also carry `Cache-Control: no-store`.

The modal contains an immediate ref guard against two clicks issuing multiple approval/execution sequences before React updates state. Its secret remains transient component state. It validates preview identity, destination and frozen documents before showing an approval control; compares the approval's entire preview against the reviewed preview; and rejects malformed acceptance responses. A generic HTTP 200 cannot be displayed as provider acceptance. Lever requires a distinct provider application identifier in addition to the local packet identifier. No provider acceptance automatically marks the local application submitted.
